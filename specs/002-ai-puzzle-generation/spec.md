# Feature Specification: AI Puzzle Generation Engine

**Feature Branch**: `feat/phase-02`

**Created**: 2026-06-04

**Status**: Draft

**Input**: User description: "The objective of Phase 2 is to replace the static puzzle repository with dynamically generated puzzles using the Gemini API. This phase transforms the game from a fixed-content experience into an endless puzzle platform capable of continuously creating new content for players. A dedicated Gemini puzzle generation service should be introduced. This service should be responsible for generating puzzle questions, answers, hints, and difficulty information. Every generated puzzle should follow a consistent structure so that the game can display and process it reliably. The service should be carefully prompted to generate puzzles that are easy for humans to solve and enjoyable for casual players. The difficulty system should be designed to heavily favor easy puzzles. During the early levels, all generated puzzles should be easy. As players progress through higher levels, medium-difficulty puzzles should gradually begin appearing, but they should remain a small percentage of the overall puzzle pool. Hard puzzles should never be generated because the target audience is casual players seeking a fun experience rather than extremely difficult challenges. Since AI-generated content can occasionally produce invalid results, a validation layer should be implemented. Every generated puzzle should be checked to ensure that it contains a valid answer, exactly three hints, reasonable question length, and safe content. Invalid puzzles should be discarded and regenerated automatically. To improve the user experience, puzzle prefetching and caching should be introduced. Future puzzles should be generated before they are needed so that players do not experience noticeable loading delays. If Gemini is unavailable or a network issue occurs, the application should automatically fall back to a local puzzle repository to ensure uninterrupted gameplay."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Endless Puzzle Play with AI-Generated Puzzles (Priority: P1)

As a player, I want to continuously play puzzles generated by the AI so that I can experience new content endlessly without running out of puzzles.

**Why this priority**: This is the core objective of the phase. Without dynamic puzzle loading, the endless gameplay experience cannot be achieved.

**Independent Test**: Start the app and verify that as you solve puzzles, new ones are seamlessly fetched and loaded from the AI generation service instead of ending the game at the previous static puzzle limit.

**Acceptance Scenarios**:

1. **Given** the player finishes a level, **When** they proceed to the next level, **Then** the game loads newly generated puzzles from the AI generation service.
2. **Given** the player is in the middle of a game, **When** they solve a puzzle, **Then** their score is updated and they can proceed to the next generated puzzle.

---

### User Story 2 - Seamless Play via Prefetching and Caching (Priority: P2)

As a player, I want puzzles to load instantly without loading indicators or spinners between levels, so that my gameplay is smooth and uninterrupted.

**Why this priority**: Essential for visual polish and maintaining player engagement. Generating puzzles on-the-fly from the API can take several seconds, creating a poor user experience if not prefetched.

**Independent Test**: Complete a level and check if the next level's puzzles are displayed instantly without a delay or loading screen.

**Acceptance Scenarios**:

1. **Given** the player is playing the current level, **When** the level begins, **Then** the system automatically triggers a background API call to prefetch and cache the puzzles for the subsequent level.
2. **Given** the prefetch cache is full, **When** the player advances to the next level, **Then** the cached puzzles are loaded instantly.

---

### User Story 3 - Offline/Network Failure Resilience (Priority: P2)

As a player, I want the game to continue working even when I am offline or when the Gemini API is unreachable, so that my session is never broken by connectivity issues.

**Why this priority**: Essential for game reliability. External APIs can fail due to rate limits, network outages, or device offline states.

**Independent Test**: Disable internet connectivity on the device/simulator and complete a level. Verify that the game transitions successfully to a fallback puzzle from the local repository.

**Acceptance Scenarios**:

1. **Given** the device has no internet connection or the Gemini API returns an error, **When** the prefetch queue attempts to pull a new puzzle, **Then** the system falls back to a puzzle from the local backup repository and continues gameplay.
2. **Given** the app has recovered from a network failure, **When** the next prefetch is triggered, **Then** it attempts to query the Gemini API again before falling back.

---

### User Story 4 - Gradual Difficulty Scaling (Priority: P3)

As a casual player, I want the puzzles to be easy at the beginning and only slightly more challenging as I reach higher levels, so that I am not frustrated by overly complex word puzzles.

**Why this priority**: Ensures appropriate gameplay balance according to user requirements.

**Independent Test**: Play through levels 1 to 5 and verify that levels 1 and 2 only contain "easy" puzzles, and levels 3+ start introducing "medium" puzzles at a low occurrence rate.

**Acceptance Scenarios**:

1. **Given** the player is on Level 1 or 2, **When** puzzles are fetched/generated, **Then** all generated puzzles have an "easy" difficulty.
2. **Given** the player is on Level 3 or higher, **When** puzzles are fetched/generated, **Then** the system introduces "medium" puzzles at a controlled low percentage (e.g., 20% chance), and never generates "hard" puzzles.

---

### Edge Cases

- **Gemini API returns structured but invalid JSON data**: The system must run the validation layer on the returned schema. If a field (e.g., hints count) is wrong, the puzzle must be discarded and a replacement requested.
- **Multiple API generation failures in a row**: If the API fails 3 consecutive times (due to rate limits or system error), the system must immediately stop retrying and pull from the local fallback repository to avoid freezing the app.
- **Content moderation flag triggered**: Puzzles containing profanity, inappropriate words, or non-alphabetic answers must fail the validation layer, be discarded, and be replaced.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The system MUST implement a service interfacing with the Gemini API to request puzzles containing a question, answer, exactly three hints, and a difficulty level.
- **FR-002**: The prompt to the Gemini API MUST specify that answers should be single words, easy for humans to solve, and suitable for a casual audience.
- **FR-003**: The system MUST implement a validation layer that verifies every generated puzzle contains:
  - A non-empty answer consisting of letters only.
  - Exactly three distinct hints.
  - A question string length between 15 and 200 characters.
  - No flagged or inappropriate terms.
- **FR-004**: The system MUST discard invalid puzzles and automatically request a replacement from the service.
- **FR-005**: The system MUST implement a prefetch queue that caches up to 3 validated puzzles in advance of the user's current puzzle.
- **FR-006**: The system MUST implement a fallback mechanism that returns a puzzle from a local static repository if the Gemini API request fails or times out (timeout threshold: 5 seconds).
- **FR-007**: The system MUST determine puzzle difficulty based on player level:
  - Level 1 & 2: 100% Easy puzzles.
  - Level 3 & 4: 90% Easy / 10% Medium puzzles.
  - Level 5+: 80% Easy / 20% Medium puzzles.
  - Hard puzzles MUST NOT be generated or loaded.

### Key Entities

- **GeneratedPuzzle**: Represents a single game puzzle generated by the AI.
  - `question`: string (15 - 200 chars)
  - `answer`: string (single word, alphabetic)
  - `hints`: array of exactly 3 strings
  - `difficulty`: enum (`easy`, `medium`)
- **PuzzleQueue**: Represents the cache of pre-fetched and validated puzzles.
  - `items`: array of `GeneratedPuzzle`
  - `maxSize`: integer (default 3)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of puzzles presented to the player must pass validation (contain a single-word answer, exactly 3 hints, and valid question length).
- **SC-002**: Transitioning to a new puzzle from the cache must take less than 100 milliseconds, ensuring zero visible lag for the user.
- **SC-003**: The local fallback repository must successfully load a backup puzzle within 500 milliseconds of a Gemini API timeout or network loss.
- **SC-004**: Under normal network conditions, the prefetch queue must maintain a minimum of 3 cached puzzles ready to play.

## Assumptions

- The Gemini API will be accessed using client-side keys defined in environment variables (e.g., `process.env.EXPO_PUBLIC_GEMINI_API_KEY`).
- The local fallback repository will contain a baseline set of at least 9 puzzles to ensure coverage of multiple levels in offline mode.
- Users are playing on standard mobile devices with occasionally unstable network connectivity.
